# Logistics: order fulfilment

The same diamond as the generic example (`a` → `b`, `c` → `d`), with domain names. The classes, fields and
audit entries are this domain's own; the dispatcher was generated by the Fluxtion compiler from
`LogisticsBuilder` and the log written by running it. Each node returns `true` only when its value changed, so an
input equal to the previous one stops at the top node.

```
        Order (a number of items)
        |
        order               holds the latest order's item count
       /     \
     pick    pack           trips = ceil(items / 20)     cartons = ceil(items / 6)
       \     /
      dispatch              books the slot: 10 min per trip + 3 min per carton; counts how often it runs
```

Inputs, in order: items = 12, 18, 18, 30.

- 18 items after 12: still one picker trip (`pick` logs `changed: false`), cartons go 2 → 3, and `dispatch`
  still runs once: `trips: 1, cartons: 3, minutes: 19, invocations: 2`. The compiler calls `pack` before
  `pick`; the siblings do not depend on each other, so either order is correct.
- **The repeated order of 18** (record 4, counting from 0, of the log's 6 records): only `order` ran, with
  `items: 18, changed: false`. There is no `dispatch` entry: no dispatch slot was booked for that order, and the
  counter stays at 2 until the order of 30 makes it 3.

## Files

| Path | What it is |
|---|---|
| `src/main/java/com/acme/diamond/domain/logistics/` | the event, the four nodes and the builder (written by hand) |
| `src/main/java/com/acme/diamond/domain/logistics/generated/LogisticsProcessor.java` | the dispatcher, generated by Fluxtion |
| `src/main/resources/com/acme/diamond/domain/logistics/generated/LogisticsProcessor.graphml` (and `.png`) | the graph the compiler derived |
| `domains/logistics/logistics-audit.yaml` | the audit log of one run |
| `domains/logistics/run-console.txt` | what the runner printed on that run |

Run it again with `java -cp target/fluxtion-diamond.jar com.acme.diamond.host.DomainMain logistics` (writes
`out/logistics-audit.yaml`). In the analyser, open `logistics-audit.yaml` with **Audit log ▸ Open log…** and the GraphML with
**Sources ▸ Open GraphML…**.
